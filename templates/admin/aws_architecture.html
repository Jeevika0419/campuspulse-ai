📋 Comprehensive AWS Service Implementation Specifications
💻
1. Amazon Elastic Compute Cloud (EC2)
Role: Cloud Deployment & App Runtime
Active
Hosts the containerized CampusPulse AI application using Docker and Gunicorn. Configured with a systemd supervisor daemon to ensure 100% uptime, automatic restarts upon system boot, and dynamic scaling.
Instance Type: t3.micro (2 vCPUs, 1GB RAM)
Container Port: 80:5000
Bootstrap Script: Embedded in CloudFormation UserData
🗄️
2. Amazon Relational Database (RDS)
Role: Managed Database Management
Active
Fully managed MySQL 8.0 database engine deployed in a private database subnet. Provides automated backups, security patching, storage autoscaling, and Multi-AZ replication readiness.
Engine: MySQL 8.0.35 • Storage: 20GB gp2
Isolation: Private subnets with 0% public internet ingress
Fallback: Seamless zero-downtime local SQLite engine
🪣
3. Amazon Simple Storage Service (S3)
Role: Scalable Secure Object Storage
Active
Stores student-submitted photo attachments and field technician resolution proof images. Employs AES-256 server-side encryption and generates time-limited presigned URLs to prevent unauthorized hotlinking.
Bucket: {{ aws_status.s3_bucket }}
Encryption: Server-Side Encryption (AES256)
Archival: Auto-transition to S3 Glacier after 90 days
🛡️
4. AWS Identity & Access Management (IAM)
Role: Security & Least-Privilege Control
Active
Adheres to the Principle of Least Privilege by binding an IAM Instance Profile directly to the EC2 host. The application obtains temporary STS credentials automatically without storing static AWS access keys in code.
Policy File: aws/iam/campuspulse_ec2_iam_policy.json
Permissions: s3:*, sns:Publish, cloudwatch:PutMetricData
Zero Key Exposure: Rotates STS tokens every 6 hours
🌐
5. Amazon Virtual Private Cloud (VPC)
Role: Network Perimeter & Subnet Isolation
Active
Establishes an isolated virtual network with dedicated public subnets for the web tier and private subnets across multiple Availability Zones for the database tier, governed by strict Security Group firewalls.
VPC CIDR: 10.0.0.0/16
Subnets: 2 Public (10.0.1.0/24), 2 Private (10.0.10.0/24)
Routing: Internet Gateway for public; zero IGW route for RDS
📊
6. Amazon CloudWatch
Role: Operational Telemetry & SLA Alarms
Active
Collects custom campus operational metrics in the CampusPulse/Infrastructure namespace. Features automated CloudWatch Alarms that evaluate SLA breaches and trigger automated escalations.
Metrics: IssuesReportedCount, SLABreachedCount
Alarm Rule: Breaches > 3 in 15 mins triggers SNS Action
Service Code: services/aws_service.py:put_metric_data()
📢

Role: Emergency Dispatch & Critical Broadcast Alerts
Active
High-throughput, push-based messaging service connecting CampusPulse AI with campus security officers, maintenance dispatchers, and department heads via SMS and Email whenever life-safety or critical facility incidents occur.
Topic ARN: {{ aws_status.sns_topic_arn }}

🎓 Project Viva & Evaluation Defense Cheat Sheet
High-Scoring Viva Answers
Q: Why did you choose Amazon EC2 instead of AWS Lambda serverless?

A: CampusPulse AI requires persistent background processes for automated SLA countdown tracking, scheduled recurrence risk model updates, and live WebSocket/heartbeat connections. EC2 with Docker provides continuous compute without execution timeout limits or cold-start latency.

Q: How does the network architecture prevent database security breaches?

A: Through Amazon VPC subnet segmentation: Amazon RDS MySQL is isolated in a private subnet with zero direct route to the Internet Gateway. The database Security Group accepts inbound connections exclusively on port 3306 from the EC2 instance's Security Group ID, neutralizing SQL brute-force attacks from the internet.

Q: Why store issue images on Amazon S3 instead of local EC2 disk?

A: Amazon S3 offers 99.999999999% (11 9s) durability, offloads media delivery bandwidth from the web application server, supports automatic lifecycle transitions to S3 Glacier for cost reduction, and generates secure time-limited presigned URLs.

Q: How does AWS IAM adhere to cloud security best practices?

A: Instead of embedding hardcoded AWS Access Keys in source code or environment variables, an EC2 IAM Instance Profile is used. The AWS STS (Security Token Service) automatically provisions and rotates temporary credentials, complying with the AWS Well-Architected Security Pillar.
